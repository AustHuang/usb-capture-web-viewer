## RC1：视频源选择与多采集卡兼容性

- 设备选择改为 `deviceId: {exact: id}`，避免切换设备时意外打开另一张采集卡。

- 默认帧率交由浏览器自动协商；参数协商失败时只在**同一设备**上回退自动模式。
- 优化同名设备区分、设备枚举竞态防护、错误诊断和 `usbCaptureDiagnostics()`。
- 完整保留 V1.6.1 的 RC7 工具栏、缩放平移、剪贴板帧复制、WebM 录制、Windows 11 Snap 布局和本机 HTTP 服务。
- Chrome 入口：`Start_Chrome_Snap.cmd`；Edge 入口：`Start_Edge_Snap.cmd`。
- 固定源码快照：`release/v1.6.2-rc1`；历史版本 `release/v1.6.1` 不变。

## 历史文档：V1.6.1

# USB Capture Web Viewer · V1.6.1

**状态：V1.6.1 正式源码发布。已通过静态与模拟测试，并获得用户上传确认；真实 Windows 11/UVC 完整验收结果尚未单独归档。**

USB Capture Web Viewer 是一个 Windows 11 的 HDMI→USB 采集卡浏览器预览和录制工具，保留 Windows 原生 Snap Layouts、画面平移/缩放与 WebM 录制。

## V1.6.1 深色直角全宽工具栏

- 最终视觉采用深色/黑色背景，顶栏 **四角全部为直角（border-radius: 0）**；标题仍靠左，参数在右侧固定两行。
- 两行分组标题「画面设置」「录制 · 缩放」使用相同的栅格列，左边缘对齐；参数标签放大、加粗。
- 保留锁定栏常驻功能，透明度开关改为「36%半透明」：开启为黑色背景 **36% 透明（64% 不透明）**，关闭是纯黑实底；文字、控件自身不透明。此设置本机记忆。
- 窄窗口每一行可单独横向滚动，标题不参与滚动。
- 本 RC7 修改仅涉及 HTML 页面 UI 和 README/CHANGELOG；**启动脚本、localhost 来源、采集/录制/复制帧逻辑沿用 RC6**。
- 已完成本地静态和模拟测试；依据用户明确上传指令发布至 GitHub。

## RC6 全宽双行工具栏（继承 RC5 快捷复制）

- 视频区域 **右键双击** 取代中键复制；第二次右键按下时直接冻结原始帧并写入剪贴板。**Ctrl+C 仍保留**。
- 重要权衡：浏览器在第一下右键时就可能打开系统菜单，因此为识别双击，视频区域内必须拦截普通单次右键菜单；使用 **Shift+右键** 可以打开原菜单。这个权衡需要实机体验后再决定是否采用正式版。
- **背景横贯整个顶部**，USB Capture 标题固定在左，控件在右并保持两行。第一行：设备、分辨率、帧率、预览、画面模式、居中、重置和全屏；第二行：录制码率、录制/结束、定位、缩放比例、锁定栏、半透明。
- **缩放仅保留百分比按钮**，悬停滚轮每档 ±10%，单击 +10%；视频区域滚轮围绕光标连续缩放不变。
- 对小窗口不增加第三行，单行内容超出宽度时可在对应行横向滚动，左侧标题始终可见。默认不锁定，仅触及顶部显示；锁定后常驻。

## RC4 原有视频帧复制（RC6 继承其核心功能）

- **RC4 历史快捷键是鼠标中键**，RC6 已将它替换为右键双击，具体操作见上文。
- **Ctrl+C**：保持本应用窗口处于活动状态，无需鼠标定位到画面上，按下即可复制；对输入框或选中的文本不会拦截原本的复制操作。
- 粘贴：在微信、画图、Word 等支持图片粘贴的应用按 **Ctrl+V**。复制成功后会短暂显示绿色确认提示。
- 复制的是 USB 采集卡原始视频帧，保留其实际分辨率；不含预览缩放、平移、浏览器操作栏或录像状态。录制过程中也可使用。
- 复制图片依赖 Chrome / Edge 的 Clipboard API 和浏览器剪贴板权限，请使用包内启动器提供的 `http://127.0.0.1:18764/` 地址。若被拒绝，检查浏览器对本地地址的剪贴板权限设置。
- 当前为 **V1.6.1 正式源码**；旧 RC 的功能演进记录保留供追溯。

## RC3 — 修复频繁摄像头授权（2026-10-18）

**原因：** 之前的启动器使用 `file://` 打开 HTML，本地文件的摄像头权限不容易以固定站点来源保存；分辨率 / 帧率每次调节还会停止旧流、重新调用 `getUserMedia()`。因此经常看到“此文件想要使用摄像头”的对话框。

**解决方式：**

1. 必须通过 `Start_Chrome_Snap.cmd`（或 PowerShell 启动器）打开。它会用 Windows 自带 PowerShell 启动仅绑定 `127.0.0.1:18764` 的本地静态网页服务；不用安装 Python、FFmpeg，也不需要管理员权限。浏览器将以固定 `http://127.0.0.1:18764/` 地址访问页面。
2. **第一次授权时请选择“访问该网站时允许”**，不要选择“仅这次访问时允许”。同一浏览器 Profile + 同一固定本地地址下，Chrome / Edge 可以记住授权；浏览器隐私设置或权限重置仍有可能使授权再次出现。
3. 滚轮改变 **分辨率 / 帧率** 将在当前 MediaStreamTrack 上调用 `applyConstraints()`，通常无需断开或再次请求摄像头；状态栏显示采集卡实际协商参数。设备真正切换时仍需重新打开对应设备。
4. 服务只侦听本机环回地址，不对局域网或互联网开放，不上传摄像头画面。浏览器每 30 秒发送一次本地心跳；关闭页面后服务会在约 2 分钟内自动退出。页面静态文件复制到 `%LOCALAPPDATA%\USB_Capture_Web_Viewer_Host`，因此不同版本仍使用相同的固定授权来源。

**注意：** 直接双击 `.html` 会重新以 `file://` 方式访问，无法享受 RC3 的固定来源授权机制；不能保证浏览器永远不再询问权限。若提示端口 18764 被占用，请先关闭占用该端口的程序，不要随意更改端口，否则浏览器会将其识别为新网站来源。

## V1.6.1 RC2/RC3 滚轮参数调节

- 六个离散参数：**设备、分辨率、帧率、码率、画面、定位** 改为无下拉箭头的单值按钮控件。鼠标悬停于当前值滚动即可逐档切换；单击切下一档，键盘方向键也可切换，不会展开下拉菜单。
- **立即生效**：画面填充模式和定位一切换立即更新；播放中切换设备、分辨率和帧率，合并连续滚轮事件后自动应用到现有采集轨道；仅设备切换时重新申请视频流，不需再点“启动预览”；未开启预览时新参数在下次启动生效。
- **安全保护**：录制期间锁定设备、分辨率、帧率和码率，防止重建采集流导致录像被切断；预览画面模式与定位仍可在录制时切换。码率在录制开始时由编码器确定，不能无损中途修改，下一次录制采用当前码率。
- 参数按钮会显示当前选项，无箭头；长设备名称被省略显示但鼠标悬停可见完整设备名。缩放只保留一个百分比数值按钮（100%～400%），滚轮每档 10% 调整；不再显示缩放滑块；视频区域滚轮仍围绕指针放大。
- 继续沿用 `--ui-*` UI 设计变量、右对齐、固定两行功能布局、悬停显示和 Win11 窗口贴靠功能。

## 操作

1. 解压整个文件夹，双击 `Start_Chrome_Snap.cmd`，允许浏览器摄像头访问。
2. 将鼠标停在 **设备 / 分辨率 / 帧率** 当前值上，滚轮切换，点击 **启动预览**。播放中继续滚轮调整会自动应用参数。
3. 需要录制时滚轮设定 **码率**，点击 **● 录制**；支持文件保存接口时会弹出 WebM 保存位置选择。
4. 点击 **■ 结束**，等待保存完成提示。不要录制中直接关闭浏览器窗口。
5. 在视频画面上滚轮缩放、放大后左键拖动；定位滚轮控件可快速查看四角；**Win + Z** 可使用 Windows 11 原生贴靠。

实际分辨率 / FPS 以采集卡和浏览器协商结果为准。录制为原始 UVC 视频流，而不是缩放后的浏览器视口，因此不会录进工具栏和 REC 提示。本版本暂不录制 HDMI 音频。

支持直接写入的浏览器会按媒体分片写入 WebM 文件；不支持文件写入接口的浏览器会在录制停止后触发下载，长时间录制可能导致内存占用较高。默认码率 8 Mbps，约 3.6 GB/小时（理论值）。

## 启动参数

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Launch_USB_Capture_Snap.ps1 -Browser Chrome -HeightPercent 34
```

- `-Browser`: `Chrome`, `Edge`, `Auto`
- `-HeightPercent`: 20–90，默认 34，竖屏底部约三分之一
- `-MonitorIndex`: 默认 -1，自动选竖屏；0 以上可指定屏幕序号

## RC6 新增开关

- **锁定栏**：打开后工具栏常驻，按钮显示「已锁定」；再次点击解锁恢复鼠标触顶显示。
